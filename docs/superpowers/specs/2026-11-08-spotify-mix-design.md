# Spotify Mix: Σχέδιο (Design)

Ημερομηνία: 2026-11-08 · Αντικαθιστά το `PLAN.md` (Φάση 0).

## 1. Τι είναι και γιατί

Ένας «DJ» για το Spotify. Ο χρήστης περιγράφει μια διάθεση και παίρνει ένα set οποιασδήποτε διάρκειας, π.χ. 6 ώρες για party. Η διάθεση μένει **σταθερή και spot on** από την αρχή ως το τέλος, όπως θα την κρατούσε ένας DJ.

Το Spotify AI Playlist (και το Spotify MCP) δεν είναι διαθέσιμο στην Ελλάδα και δεν έχει δημόσιο API. Το Spotify δεν δίνει πια σε νέες εφαρμογές ούτε στοιχεία ήχου ούτε προτάσεις tracks. Αυτό το app καλύπτει το κενό.

**Η αξία βρίσκεται σε τρία πράγματα, με αυτή τη σειρά σημασίας:**
1. **Επιλογή:** κάθε track ταιριάζει ταυτόχρονα σε **διάθεση**, **είδος** και **περιγραφή ήχου**.
2. **Σειρά:** κάθε μετάβαση δένει, και η ενέργεια μένει σταθερή με μικρά κύματα (λίγη ένταση, λίγη ανάσα), ώστε να μην κουράζει.
3. **Κοψίματα ως εργαλείο σειράς:** ένα track 5 λεπτών που θα έριχνε το vibe μπορεί να παίξει μόνο 2 λεπτά, το ανεβαστικό του κομμάτι ή αυτό που κάνει γέφυρα, ώστε να πετύχει το ζητούμενο. **Ποτέ δύο tracks ταυτόχρονα.**

## 2. Στόχοι, μη-στόχοι, anti-goals

**Στόχοι (v1)**
- Login με Spotify για **οποιονδήποτε** με Premium, μέσω δικού του Spotify Client ID και οδηγού μέσα στο app.
- Τρεις πηγές tracks: (α) μια playlist του χρήστη, (β) τα Saved / Liked Songs, (γ) όλο το Spotify.
- Ζητούμενο είτε με **ελεύθερο κείμενο** (δωρεάν AI) είτε με **φόρμα**.
- Οποιαδήποτε διάρκεια, από 30 λεπτά ως 6+ ώρες.
- Αποτέλεσμα: **νέα** playlist στο Spotify με τη σωστή σειρά, και **αναπαραγωγή με κοψίματα** από το app.
- Είδη: **house / techno** πρώτα.

**Μη-στόχοι (v1)**
- Blends ή επικάλυψη tracks (απαγορεύεται από την πολιτική του Spotify και δεν το θέλει ο χρήστης).
- Αυτόματη ρύθμιση του Spotify Mix (δεν υπάρχει API).
- Άλλα είδη πέρα από house/techno. Η αρχιτεκτονική όμως πρέπει να τα επιτρέπει με config (§7).
- Αξιόπιστη αναπαραγωγή με κοψίματα από κινητό. Στόχος είναι το laptop, και το κινητό είναι «όσο πάει».
- Λογαριασμοί, βάση δεδομένων ή αποθήκευση δεδομένων χρηστών σε δικό μας server.
- Κοινή χρήση διορθώσεων κοψιμάτων ανάμεσα σε χρήστες.

**Anti-goals: αποτυχία ακόμα κι αν «δουλεύει»**
- Ένα track που **σπάει το vibe** (ταιριάζει σε 2 από τα 3: διάθεση, είδος, ήχο). Καλύτερα λιγότερα tracks παρά ένα ξένο.
- Κόψιμο **στη μέση φράσης** που ακούγεται άτσαλο.
- Οποιαδήποτε αλλαγή σε υπάρχουσα playlist ή βιβλιοθήκη του χρήστη.
- Να χρειάζεται ο χρήστης κλειδί AI ή να πληρώνει οτιδήποτε.
- Χρήση κρυφών/ανεπίσημων API του Spotify.

## 4. Αρχιτεκτονική

```
[Browser: GitHub Pages, React + TypeScript + Vite (υπάρχων κώδικας)]
  ├─ Setup: οδηγός για δικό του Spotify Client ID (αποθήκευση σε localStorage)
  ├─ Login: PKCE (υπάρχει, src/spotify/auth.ts)
  ├─ Πηγές: playlist / saved / όλο το Spotify
  ├─ Μηχανή: spec → υποψήφια → φίλτρο → σειρά → κοψίματα (καθαρή TypeScript, unit tests)
  ├─ Δημιουργία νέας playlist στο Spotify
  └─ Set player: εκτελεί τα κοψίματα (§5.7)
            │
            ▼
[Cloudflare Worker, δωρεάν πλάνο]
  ├─ POST /spec: κείμενο → set spec μέσω Cloudflare Workers AI (δωρεάν ημερήσιο όριο, μικρό μοντέλο)
  │    · δέχεται μόνο έγκυρο Spotify access token (το επαληθεύει με GET /v1/me)
  │    · όριο χρήσης ανά Spotify user id
  │    · όταν εξαντληθεί το ημερήσιο όριο → το app πέφτει στη φόρμα με σχετικό μήνυμα
  ├─ GET /tags: tags είδους/ήχου από Last.fm (δωρεάν κλειδί του owner)
  └─ (όπου χρειαστεί) proxy για πηγές χωρίς CORS, π.χ. Deezer
```

Όλα τα δεδομένα του χρήστη (tokens, cache, διορθώσεις) μένουν στον browser του. Ο Worker δεν αποθηκεύει τίποτα πέρα από μετρητές ορίων.

## 5. Πώς δουλεύει

### 5.1 Set spec (η «προδιαγραφή» του set)
Κεντρική δομή. Η μηχανή δουλεύει **μόνο** με αυτήν και δεν βλέπει ποτέ το αρχικό κείμενο. Ενδεικτικά πεδία:
- είδος/υπο-είδη (π.χ. melodic techno, deep house), εύρος BPM
- στόχος ενέργειας (0–1) και πλάτος «κυμάτων»
- valence (σκοτεινό ↔ φωτεινό), χορευτικότητα, φωνητικά (όχι / λίγα / ναι)
- λέξεις περιγραφής ήχου (π.χ. «ζεστό bass», «ατμοσφαιρικό»)
- καλλιτέχνες/tracks αναφοράς (προαιρετικά), διάρκεια set, στυλ κοψίματος

**Κείμενο → spec:** ο Worker καλεί το Workers AI και ζητά JSON με συγκεκριμένο σχήμα, που επικυρώνεται πριν χρησιμοποιηθεί. **Φόρμα → spec:** απευθείας. Ο χρήστης βλέπει το spec που βγήκε και μπορεί να το διορθώσει πριν συνεχίσει.

### 5.2 Υποψήφια tracks
- **Playlist / Saved:** όλα τα tracks της πηγής.
- **Όλο το Spotify:** συνδυασμός από (1) καλλιτέχνες/tracks που προτείνει το AI ως μέρος του spec, (2) Spotify search με όρους είδους/ύφους, (3) ReccoBeats recommendations με seeds από tracks που έχουν ήδη επαληθευτεί. **Κάθε track επαληθεύεται ότι υπάρχει στο Spotify** πριν μπει στη δεξαμενή, γιατί το AI μπορεί να «εφεύρει» τίτλους.
- Στόχος: δεξαμενή αρκετά μεγαλύτερη από όσα χρειάζεται το set (π.χ. ×2), ώστε το φίλτρο να μπορεί να είναι αυστηρό.

### 5.3 Στοιχεία ήχου ανά track
Χρειάζονται: BPM, key (Camelot), ενέργεια, valence, χορευτικότητα, instrumentalness/φωνητικά, διάρκεια.
Σειρά πηγών (υπάρχει μερικώς στο `src/data/features.ts`):
1. ReccoBeats με Spotify ID.
2. ReccoBeats/Deezer μέσω ISRC, για tracks που υπάρχουν με άλλο release ID.
3. Deezer BPM (μέσω του Worker).
4. **Επιλογή του builder:** ανάλυση του δωρεάν 30″ preview του Deezer στον browser (π.χ. Essentia.js) για BPM/key/ενέργεια. Χρειάζεται έλεγχο όρων χρήσης πριν υιοθετηθεί.

**Είδος και περιγραφή ήχου** (το ReccoBeats δεν τα δίνει):
1. **Last.fm tags** για το track, και για τον καλλιτέχνη αν λείπουν (π.χ. «deep house», «melodic techno», «atmospheric», «dark», «vocal»), μέσω του Worker.
2. ~~**Spotify artist genres**~~: ελέγχθηκε 2026-11-09, το πεδίο έρχεται άδειο σε Dev Mode (0/276 καλλιτέχνες). Αφαιρέθηκε.
3. Χαρακτηριστικά ήχου που συμπληρώνουν την «περιγραφή» (valence, ενέργεια, instrumentalness, acousticness).
4. Ταξινόμηση από το AI **μόνο** για όσα μένουν ακαθόριστα, σε μικρές παρτίδες και μέσα στο ημερήσιο όριο. Δεν είναι η κύρια πηγή.

**Πότε ένα track έχει «αρκετά στοιχεία»:** **BPM υποχρεωτικό**, γιατί χωρίς αυτό δεν γίνεται ούτε σειρά ούτε κόψιμο. Key και ενέργεια προαιρετικά, αλλά όταν λείπουν το track βαθμολογείται χαμηλότερα. Επίσης χρειάζεται τουλάχιστον ένα σήμα είδους (tag ή genre).

Cache στον browser. Το «δεν βρέθηκε» **δεν** αποθηκεύεται μόνιμα (γνωστό bug σήμερα): λήγει μετά από λίγες μέρες.
Γνωστό ρίσκο: στο House playlist του χρήστη (526 tracks) η κάλυψη μόνο από ReccoBeats ήταν ~40%.
**Μέτρηση 2026-11-09 (531 tracks):** ReccoBeats 212 (40%), Deezer 0. Για τα υπόλοιπα 319 το Deezer έχει το track αλλά με `bpm: 0` (19/20 δείγμα) ή καθόλου (1/20). Κάλυψη 28% → **no-go**. Ταβάνι με τις σημερινές πηγές: 40%, γιατί μόνο το ReccoBeats δίνει ενέργεια/διάθεση. Άρα η ανάλυση preview (§5.3.4) είναι απαραίτητη.

### 5.4 Φίλτρο (επιλογή)
- Κάθε track παίρνει βαθμό ταιριάσματος σε **διάθεση**, **είδος** και **ήχο** χωριστά. Μπαίνει μόνο αν περνά **και τα τρία** κατώφλια.
- Tracks χωρίς επαρκή στοιχεία: **δεν μπαίνουν** από προεπιλογή. Ο χρήστης βλέπει πόσα αποκλείστηκαν και γιατί, και μπορεί να τα συμπεριλάβει χειροκίνητα.
- Αν η πηγή δεν φτάνει για τη ζητούμενη διάρκεια, το app το λέει καθαρά: «βρέθηκαν 3 ώρες που ταιριάζουν». Δεν γεμίζει με ξένα tracks. Για «όλο το Spotify» ψάχνει περισσότερα.

### 5.5 Κοψίματα (ποιο κομμάτι κάθε track)
Η δομή του track βγαίνει από:
1. **Πλέγμα φράσεων** (house/techno): bar = 240/BPM, φράσεις 16/32 bars, πρότυπο intro → groove → breakdown → drop → outro. Υπάρχει αρχή στο `planSegment` στο `src/mix/music.ts`.
2. **Συγχρονισμένοι στίχοι** (LRCLIB, δωρεάν) για tracks με φωνητικά: εντοπισμός ρεφρέν/επαναλήψεων και ευθυγράμμιση με το πλέγμα.
3. **Διορθώσεις χρήστη:** ±1 φράση ενώ ακούει. Αποθηκεύονται τοπικά και έχουν πάντα προτεραιότητα.

Ποιο τμήμα κρατάμε εξαρτάται από τον **ρόλο του track στη θέση του**: ολόκληρο, groove + drop, μόνο το ανεβαστικό, ή σύντομη γέφυρα ανάμεσα σε δύο tracks που αλλιώς δεν δένουν. Κανόνες:
- Start/end **πάντα** σε αρχή φράσης.
- Ελάχιστο μήκος τμήματος (πρόταση: ~64 bars, ≈2′ στα 128 BPM).
- Στο UI υπάρχει επιλογή «στυλ κοψίματος» (ολόκληρα / club / γρήγορο), που ορίζει πόσο επιθετικά κόβει.

### 5.6 Σειρά
Κόστος μετάβασης A → B: διαφορά BPM (έως ~6%, ή μισό/διπλό), συμβατότητα Camelot (ίδιο, ±1, A↔B), απόκλιση ενέργειας από την **καμπύλη-στόχο**. Η καμπύλη είναι σταθερή γύρω από τον στόχο του spec, με μικρά κύματα. Επιτρέπεται αργή ολίσθηση BPM μέσα στο εύρος, αλλά όχι άλματα.
Λύση: greedy αρχική σειρά + βελτίωση 2-opt. Πρέπει να τρέχει στον browser για ~150 tracks σε λίγα δευτερόλεπτα.
Η σειρά και τα κοψίματα αποφασίζονται **μαζί**: ένα κόψιμο-γέφυρα μπορεί να κάνει δυνατή μια μετάβαση.

### 5.7 Αποτέλεσμα και αναπαραγωγή
1. **Νέα playlist** στο Spotify με τη σειρά, με όνομα και περιγραφή από το spec. Δεν αγγίζουμε τίποτα υπάρχον.
2. **Set player** στο app: για κάθε track παίζει από start ως end, με γρήγορο fade-out → άλμα → fade-in (λίγο κάτω από 1″, ρυθμιζόμενο).
   - **Κύριος τρόπος: έλεγχος συσκευής Spotify Connect** μέσω Web API (play με position, seek, volume). Η συσκευή είναι συνήθως το **Spotify desktop app στο ίδιο laptop**, αλλά μπορεί να είναι και άλλη (ηχείο, κινητό). Ο ήχος παίζει από το Spotify, άρα **αν κλείσει ή κολλήσει το tab, η μουσική συνεχίζει** με ολόκληρα tracks. Αν η συσκευή δεν υποστηρίζει volume, κόβει χωρίς fade.
   - **Εφεδρικός:** player μέσα στον browser (Web Playback SDK, υπάρχει στο `src/spotify/player.ts`), για όποιον δεν έχει Spotify app. Εδώ το tab **είναι** η συσκευή: αν κλείσει, η μουσική σταματά. Το UI το λέει καθαρά.
   - Χρονισμός: οι timers πρέπει να αντέχουν σε κρυφό tab (π.χ. Web Worker timers, και έλεγχος της πραγματικής θέσης αναπαραγωγής πριν από κάθε κόψιμο). Αν το app «χάσει» ένα κόψιμο, συγχρονίζεται ξανά με ό,τι παίζει και συνεχίζει.
   - Το app δείχνει τι παίζει, τι ακολουθεί και τον χρόνο ως το επόμενο κόψιμο. Υπάρχει παύση και skip.
   - **Αν το app σταματήσει**, η μουσική συνεχίζει στο Spotify με ολόκληρα tracks. Το app πρέπει να μπορεί να «ξαναπιάσει» το set από το track που παίζει.
3. Το set (spec, σειρά, κοψίματα) αποθηκεύεται τοπικά, ώστε να ξαναπαίζει χωρίς νέο υπολογισμό.

## 6. Οθόνες (ενδεικτικά, ελληνικό UI)
1. **Setup** (μία φορά): οδηγός βήμα-βήμα για Spotify app → Client ID, με το σωστό Redirect URI προς αντιγραφή.
2. **Νέο set:** πηγή (playlist / saved / όλο το Spotify) + κείμενο ή φόρμα + διάρκεια + στυλ κοψίματος.
3. **Έλεγχος spec:** τι κατάλαβε το app, με δυνατότητα διόρθωσης.
4. **Αποτέλεσμα:** λίστα με σειρά, τμήμα κάθε track και αποκλεισμένα tracks με αιτία. Κουμπιά «Φτιάξε playlist» και «Παίξε το set».
5. **Player:** τρέχον/επόμενο, χρονόμετρο κοψίματος, διόρθωση σημείου ±1 φράση.

## 7. Επεκτασιμότητα ειδών
Όλα όσα εξαρτώνται από το είδος μπαίνουν σε **προφίλ είδους** (config, όχι κώδικας): εύρος BPM, μήκος φράσης, πρότυπο δομής, ανοχές μετάβασης, ελάχιστο μήκος τμήματος. Το v1 έχει μόνο house/techno.

## 9. Τι αποφασίστηκε και από ποιον

**Από τον χρήστη**
- Η επιλογή tracks (διάθεση + είδος + ήχος) είναι το πιο σημαντικό. Μετά έρχεται η σειρά.
- Σταθερή διάθεση, όπως την κρατά ένας DJ.
- Κοψίματα ναι, ποτέ δύο tracks μαζί.
- Τελικό προϊόν στο Spotify. Το app μένει ανοιχτό (laptop) για να εκτελεί τα κοψίματα (δρόμος «C»).
- Τρεις πηγές: playlist, saved, όλο το Spotify. Πάντα **νέα** playlist.
- Ξεκινάμε με house/techno.
- Ο καθένας με δικό του Spotify Client ID, με οδηγό.
- Χωρίς κλειδί AI για τον χρήστη: δωρεάν AI σε Worker, χωρίς κόστος.

**Δικές μου αποφάσεις (μπορούν να αλλάξουν)**
- AI: Cloudflare Workers AI αντί για Gemini, γιατί το δωρεάν Gemini απαγορεύεται για χρήστες στον ΕΟΧ.
- Είδος/ήχος από Last.fm tags (+ Spotify genres αν υπάρχουν). Το AI χρησιμοποιείται μόνο συμπληρωματικά.
- «Αρκετά στοιχεία» = BPM + ένα σήμα είδους. Κατώφλι go στη Φάση 0: ≥80%.
- Κύριος player: Spotify Connect, ώστε η μουσική να συνεχίζει αν κλείσει το tab. Εφεδρικός: browser player.
- Χτίζουμε πάνω στον υπάρχοντα κώδικα (React + TS + Vite, GitHub Pages).
- Υπάρχει φόρμα ως εναλλακτική του κειμένου.
- Οι διορθώσεις κοψιμάτων μένουν τοπικά στον browser.
- Ο Worker δέχεται μόνο συνδεδεμένους χρήστες Spotify, με όριο ανά χρήστη.
- Tracks χωρίς στοιχεία δεν μπαίνουν από προεπιλογή.

## 10. Ρίσκα
1. **Κάλυψη στοιχείων ήχου** (~40% σήμερα). Αν μείνει χαμηλή, το φίλτρο αποκλείει πολλά και τα sets από playlist μικραίνουν.
2. **Ποιότητα δωρεάν AI:** τα μικρά μοντέλα μπορεί να μην «πιάνουν» niche house/techno prompts.
3. **Ημερήσιο όριο Workers AI**, που μοιράζεται σε όλους τους χρήστες. Μετά το όριο μένει μόνο η φόρμα ως την επόμενη μέρα.
4. **Χρονισμός στο παρασκήνιο:** ο Chrome επιβραδύνει τους timers σε κρυφά tabs. Στον κύριο τρόπο (Connect) το tab δεν παράγει ήχο, οπότε κινδυνεύει περισσότερο. Ελέγχεται στη Φάση 0 (δ).
5. **Ακρίβεια κοψιμάτων** χωρίς πραγματική ανάλυση ήχου.

## 11. Στην κρίση του builder

- Αν θα χρησιμοποιηθεί ανάλυση preview (§5.3.4), μετά από έλεγχο όρων.
- Ανίχνευση ρεφρέν από στίχους.
- UI/εμφάνιση, μέσα στο πλαίσιο του §6.
